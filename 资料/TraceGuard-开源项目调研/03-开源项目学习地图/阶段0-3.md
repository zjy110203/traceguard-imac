# TraceGuard v1.1 团队学习路线：阶段 0–3

## 本阶段区间定位

本册覆盖 v1.1 的工程基座、受控被测应用、确定性执行内核，以及任务调度/执行编排/测试管理工作台（阶段 0～3）。四阶段共同回答"如何可信地产生一次测试结果"：阶段 0 建立可复现、可协作、可持续集成的工程与安全基线；阶段 1 用 TeamFlow 提供带 Ground Truth 的可控场景与故障注入；阶段 2 交付"Playwright 负责确定性执行、Oracle 独立于 Agent"的测试内核；阶段 3 把内核接入持久化、异步、可追踪的 Task/Run/Step 平台。本区间内 Event/Evidence 仅做最小留痕，完整证据基础设施自阶段 4 起；诊断、图推理、自愈与 Benchmark 均在后续阶段，不在本区间实现。

> 角色简称（职能分工，非新增概念）：平台工程师（工程基座/CI/编排/部署）、执行内核工程师（Playwright + pytest）、Agent 工程师（Explorer/Compiler/Diagnosis/Planner/Repair）、证据工程师（Event/Evidence/Graph/PostgreSQL）、评测工程师（UI-FaultBench/指标）、安全工程师（安全基线/Tool Gateway/ZAP/可靠性）、工作台工程师（Vue 工作台/FastAPI/可视化）。
> 阶段名称严格采用 v1.1 正式名称；边界口径与《TraceGuard 十四阶段开源项目映射》《指定项目官方信息核实记录》一致。
