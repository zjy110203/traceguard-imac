# TraceGuard 项目总览与需求范围

-   项目名称：TraceGuard
-   英文定位：Agentic Web UI Testing & Quality Intelligence Platform
-   架构基线：v1.1
-   状态：总体定位与范围基线；详细验收指标待评测设计冻结

## 1. 项目定位

TraceGuard 是一个基于 AI Agent 的智能 Web UI 自动化测试与质量诊断平台。

平台将 Agent 自主探索、测试用例编译、确定性自动化执行、可信
Oracle、证据关联、主动故障诊断和受保护的测试资产修复结合起来，目标是降低
Web UI
测试设计、执行维护和故障排查成本，同时提高测试结论的可信度、可解释性和可追溯性。

TraceGuard 不是单纯的浏览器自动化工具，也不是只会生成 Playwright
脚本的代码助手。它关注从测试需求到质量改进的完整工程闭环。

## 3. 项目目标

### 3.1 产品目标

1.  从自然语言需求形成结构化 TestIntent。
2.  Agent 探索 Web 应用并记录 Exploration Trace。
3.  将探索轨迹编译为可审核、可重复执行的 TestCase。
4.  使用可信 Oracle 和确定性执行机制判定测试结果。
5.  统一采集执行事件和多源证据。
6.  建立证据关联关系，分析支持、反驳和冲突。
7.  支持多假设故障诊断和受权限约束的主动探针。
8.  区分产品缺陷、测试资产问题、环境问题和不确定情况。
9.  安全修复测试资产，并经过审批和回归验证。
10. 通过 Benchmark 和对照实验评价各项能力。

### 3.2 工程目标

-   核心对象具有清晰领域边界和唯一业务写入者。
-   Task、Run、Step 等对象具备明确生命周期。
-   Event 具备可追溯、幂等和可恢复机制。
-   Evidence 保留来源、完整性、派生关系和关联信息。
-   Agent 工具调用受到权限策略约束。
-   业务状态以权威持久化存储为准，不由模型文本决定。
-   核心能力可通过契约测试、集成测试和 Benchmark 验证。

### 3.3 研究目标

重点验证四项技术特色： 1. TestCase
Compiler：探索轨迹能否转化为稳定测试资产。 2. Evidence Correlation
Graph：多源证据关联是否改善故障解释。 3. Active Diagnosis
Planner：主动选择探针是否提高诊断效率。 4. Oracle-Protected
Self-Healing：能否修复测试资产而不削弱断言。

## 5. 核心业务闭环

``` mermaid
flowchart TD
    A["① 需求理解与测试规划"]
    B["② 自主探索与测试生成"]
    C["③ 确定性测试执行"]
    D["④ 证据采集与关联"]
    E["⑤ 故障诊断与处置"]
    F["⑥ 安全修复与回归优化"]

    A --> B --> C --> D --> E --> F
    F -->|"新版本测试资产 / 回归"| C
    F -->|"覆盖反馈"| A
```

1.  需求理解：确定业务行为和预期来源。
2.  探索生成：探索应用并形成候选测试。
3.  确定性执行：使用正式 TestCase 和 Oracle 执行。
4.  证据关联：收集并组织执行事实。
5.  故障诊断：解释失败、补充探针、确定处置方向。
6.  安全修复：修复符合条件的测试资产并回归。

## 6. 功能需求

### 6.1 测试需求与资产

-   创建和管理 TestIntent。
-   维护需求来源和版本引用。
-   管理 TestCase、TestCaseVersion。
-   支持候选用例、审核和正式晋升。
-   管理测试数据、前置条件和清理策略。
-   管理 OracleSpec 及审核记录。

### 6.2 Agent 探索与生成

-   浏览器页面理解。
-   元素和交互识别。
-   业务路径探索。
-   Exploration Trace 记录。
-   候选步骤和断言生成。
-   Locator 稳定性检查。
-   候选 TestCase 编译和回放验证。

### 6.3 执行管理

-   创建 Task、调度 Run、管理 Step。
-   支持超时、取消、重试和失败恢复。
-   保存执行环境和版本信息。
-   产生 Test Verdict。
-   收集执行事件和附件。

### 6.4 证据与诊断

-   统一 Event 接入。
-   保存原始和规范化 Evidence。
-   建立 EvidenceEdge。
-   支持 supports、contradicts 等关系。
-   管理 Hypothesis。
-   执行只读 Probe。
-   输出 Diagnosis。
-   保留不确定性和冲突信息。

### 6.5 故障处置与修复

-   故障分类和处置路由。
-   产品缺陷记录。
-   环境和数据问题处置。
-   Flaky 特征分析。
-   RepairProposal 生成。
-   Diff 检查、断言保护和沙箱验证。
-   人工审批。
-   TestCaseVersion 晋升和回滚。
-   回归验证。

### 6.6 平台与评测

-   项目和应用管理。
-   测试资产管理。
-   执行中心和实时状态展示。
-   证据和诊断工作台。
-   修复审核工作台。
-   Benchmark 数据集、实验和结果展示。
-   审计、权限和数据保留管理。

## 7. 非功能需求

  类别       要求方向
  ---------- ----------------------------------------------
  可信性     Oracle 缺失不能被解释为通过
  可追溯性   结果追溯到 TestCase、Oracle、Run 和 Evidence
  可复现性   保留执行版本、配置、测试数据和环境信息
  安全性     最小权限、浏览器隔离、网络限制和审计
  可恢复性   支持任务重试、事件重放和工作流恢复
  可扩展性   支持新增探针、Agent 和数据源
  可观测性   记录系统日志、指标、Trace 和业务事件
  可维护性   统一契约、类型校验和自动化测试

性能目标、并发量、资源上限、SLO
和保留周期尚未冻结，应通过实际负载和部署条件确定。

## 8. 项目范围

### 8.1 纳入范围

Web UI 自动化、Agent 自主探索、AI 辅助测试生成、TestCase
Compiler、Trusted Oracle、Playwright 确定性执行、Evidence
Graph、故障诊断、主动探针、受保护测试自愈、回归验证、Flaky
分析、UI-FaultBench 和外部应用泛化验证。

### 8.2 当前不作为核心目标

-   自动修改被测产品业务代码；
-   自动创建和合并代码 PR；
-   无审核地修改正式 TestCase；
-   无审核地修改 Oracle；
-   无约束 Agent Swarm；
-   全面微服务化；
-   强制引入图数据库；
-   完整商业 SaaS 多租户能力；
-   原生移动 App 自动化；
-   完全替代人工测试人员。

Risk-Based Regression Optimization
定位为后续扩展，不作为当前四项核心技术特色之一。

## 9. 首期最小纵向切片

以 TeamFlow 的"创建项目"业务作为首条端到端链路： - 人工编写并审核
TestCase； - 人工定义并审核 OracleSpec； - Playwright 确定性执行； -
采集 Event 和 Evidence； - 建立基础 Evidence Graph； - 使用规则和 LLM
辅助诊断； - 执行少量授权只读探针； - 输出 Diagnosis 和 Disposition； -
展示完整报告。

首期暂不要求自主探索全流程、复杂贝叶斯诊断和自动修复正式测试资产。

## 10. 成功评价维度

  维度         核心问题
  ------------ --------------------------------------------
  测试生成     候选用例是否正确、稳定、可回放
  测试可信度   能否避免错误预期和 False Pass
  证据质量     证据是否完整、可关联、可追溯
  诊断能力     故障分类和主要根因判断是否准确
  诊断效率     主动探针是否降低排查成本
  修复安全     是否保持原始断言并避免引入回归
  泛化能力     离开 TeamFlow 后是否仍有有效探索和执行能力

具体指标和实验口径见 Benchmark 文档。
