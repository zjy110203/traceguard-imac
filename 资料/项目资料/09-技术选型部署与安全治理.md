# TraceGuard 技术选型、部署与安全治理

-   架构基线：v1.1
-   状态：技术选型方向基线；具体版本、容量和安全策略待实施前冻结

## 1. 技术选型总览

  方向                 建议技术               主要职责
  -------------------- ---------------------- ------------------------------
  后端语言             Python                 业务、Agent、诊断和数据处理
  API                  FastAPI                平台 API
  数据校验             Pydantic               请求、响应和配置校验
  ORM                  SQLAlchemy             数据访问
  主数据库             PostgreSQL             业务状态和核心数据
  消息与缓存           Redis                  Broker、缓存
  异步任务             Celery                 Worker 调度和任务分发
  Agent 工作流         LangGraph              有状态 Agent 工作流
  确定性浏览器自动化   Playwright             正式测试执行
  浏览器 Agent         Browser Use            自主探索和自然语言浏览器操作
  测试框架             pytest                 自动化测试组织
  前端                 Vue 3                  平台工作台
  前端语言             TypeScript             类型安全
  实时通信             SSE                    状态和事件推送
  对象存储             MinIO / 兼容对象存储   截图、视频、HAR、附件
  可观测性             OpenTelemetry          日志、指标、Trace
  容器化               Docker Compose         本地开发和集成环境

具体依赖版本和兼容矩阵应在工程启动前锁定，不能仅凭技术名称认为兼容。

## 2. 关键技术职责边界

### 2.1 Playwright 与 Browser Use

  ------------------------------------------------------------------------------
  维度                    Playwright                    Browser Use
  ----------------------- ----------------------------- ------------------------
  主要定位                确定性执行                    Agent 自主探索

  输入                    正式 TestCase                 自然语言目标、上下文

  操作方式                明确步骤和 Locator            Agent 规划和工具调用

  结果判定                确定性 Assertion / Oracle     不直接决定正式 Test
                                                        Verdict

  可重复性                目标是稳定回放                探索轨迹需要编译和验证

  输出                    Run、Step、Event、Assertion   Exploration
                          Result                        Trace、候选场景
  ------------------------------------------------------------------------------

Browser Use 探索成功不能直接替代正式测试通过。

### 2.2 Celery 与 LangGraph

  组件         负责                        不负责
  ------------ --------------------------- --------------------
  FastAPI      API 接入、鉴权、查询        长时间工作流
  PostgreSQL   权威业务状态                Agent 推理
  Celery       异步任务分发、Worker 调度   Agent 内部推理
  LangGraph    Agent 节点和有状态工作流    全平台任务队列
  Redis        Broker、缓存                权威业务状态
  Worker       执行任务                    业务状态的随意裁决

LangGraph Checkpoint 可以用于工作流恢复，但不能形成与 PostgreSQL
冲突的第二套业务状态。

## 4. 运行组件职责

### 4.1 API 服务

-   用户身份和权限校验；
-   创建、查询业务对象；
-   提交异步任务；
-   提供报告和证据查询；
-   提供 SSE 订阅入口。

### 4.2 Celery Worker

建议按能力划分 Worker 队列： - execution； - exploration； -
diagnosis； - probe； - repair-validation； - benchmark。

具体是否独立进程、容器或队列，需要根据资源和安全要求确定。

### 4.3 浏览器执行环境

每个 Run 应具备隔离浏览器上下文和清理机制。

外部不可信应用应使用更严格的执行进程或容器隔离，限制网络、文件系统、凭证、进程能力和资源消耗。

### 4.4 数据存储

-   PostgreSQL：权威业务状态；
-   Redis：短期缓存和任务 Broker；
-   MinIO：大文件和证据附件；
-   LangGraph Checkpoint：工作流恢复信息；
-   Audit Log：管理和敏感操作记录。

## 5. Security & Privacy Governance

### 5.1 威胁面

  威胁                     风险
  ------------------------ ----------------------------------
  Prompt Injection         网页内容诱导 Agent 越权
  SSRF                     访问 localhost、内网或云元数据
  DNS Rebinding            域名解析变化绕过初始检查
  Redirect Abuse           重定向到未授权目标
  Credential Leakage       凭证进入 Prompt、日志或截图
  Cross-Workspace Access   跨项目读取数据
  Unsafe Tool Call         未授权文件、Shell 或网络操作
  Evidence Leakage         截图、DOM、HAR 包含敏感数据
  Resource Exhaustion      无限循环、长时间运行和大规模下载
  Supply Chain Risk        依赖、浏览器或工具版本存在风险

### 5.2 安全控制

  控制层              要求
  ------------------- ------------------------------------
  Identity            用户、服务和 Agent 身份可识别
  Authorization       Workspace、项目、对象级权限
  Tool Gateway        每次工具调用检查权限和参数
  Browser Isolation   浏览器上下文和执行进程隔离
  Network Egress      域名白名单、出站限制、内网地址阻断
  DNS                 解析结果和实际连接目标校验
  Redirect            每次重定向重新检查
  Credentials         密钥加密存储，按需短期提供
  File System         限定工作目录和读写范围
  Prompt Injection    页面内容视为不可信数据
  Evidence Privacy    截图、DOM、请求和日志脱敏
  Audit               记录主体、动作、目标、时间和结果
  Retention           明确保留、过期和删除策略

### 5.3 TeamFlow 与 External Web Apps 安全差异

TeamFlow 是受控应用，可以提供经授权的测试 API、业务状态查询和故障注入。

External Web Apps 是不可信目标： - 默认不开放任意内网访问； -
默认不提供高权限凭证； - 不允许 Agent 任意访问本地文件； -
只允许批准的网络目标； - 页面内容不具备工具授权能力； -
高风险操作需要明确审批或禁止。

### 5.4 Prompt Injection 防护

页面内容、DOM、网页文本、网络响应和下载文件均视为不可信数据。

不得： - 让网页内容覆盖系统指令； - 让网页内容直接授予工具权限； -
根据网页文本自动向任意目标发送凭证； - 允许 Agent 绕过工具网关。

防护必须由权限网关、网络层和隔离执行环境落实，而不是只依赖 Prompt。

## 6. 安全验收用例

  测试场景                预期结果
  ----------------------- ----------------
  跨 Workspace 读取资源   拒绝
  访问 localhost          阻断
  访问内网地址            阻断
  DNS 解析到内网 IP       阻断
  重定向到未授权目标      阻断
  未授权工具调用          拒绝
  页面诱导读取 Cookie     不暴露凭证
  页面诱导执行 Shell      不执行
  未批准文件写入          拒绝
  敏感字段进入普通日志    脱敏
  超出执行预算            终止或限流
  证据过期                按保留策略处理

## 7. 可观测性

系统至少需要三类观测：

1.  平台运行观测：API 延迟、Worker 队列、资源、错误率。
2.  工作流观测：Agent 节点、模型调用、工具调用、Checkpoint。
3.  业务执行观测：Task、Run、Step、Event、Evidence、Diagnosis。

OpenTelemetry 可用于技术 Trace、Metrics 和 Logs。业务 Event 和 Evidence
仍需使用 TraceGuard 自身契约管理，不能把技术 Trace 直接等同于业务证据。

## 8. 可靠性与恢复

需要设计： - Worker 心跳； - 任务超时； - 取消确认； - 幂等任务提交； -
Event 重试； - 死信队列； - 事件重放； - 工作流 Checkpoint； -
对象存储附件完整性检查； - 浏览器资源回收； - 失败补偿和孤儿资源清理。
