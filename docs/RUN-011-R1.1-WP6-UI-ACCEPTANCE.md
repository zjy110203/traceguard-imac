## 3. 结构性缺口（如实登记）

前端各视图把 `workspace_id=default` 硬编码在查询串中（`App.vue`、`DashboardView.vue`、
`TestCasesView.vue`、`IntentsView.vue`、`RunsView.vue` 等），**没有 workspace 切换控件**。
因此 UI 无法切换到 `ws-run011-r1-1` 等非 default workspace。这不是本轮新增缺陷，而是既有
产品缺口。本轮不伪装它有切换能力，也不因缺少该控件而宣称 UI 覆盖了多 workspace 验收。

跨 Workspace 的数据边界由 API 层完整验证：
`tests/integration/test_workspace_isolation_run011_r1_1.py`（23 passed，见 WP1 报告）。

## 4. 审核成功路径的覆盖范围

UI 手工创建的用例断言未绑定已审批 Oracle，服务端审核门禁返回
`ORACLE_BINDING_INCOMPLETE: MISSING_ORACLE`，状态保持 PENDING——这是**门禁正确生效**，
不是缺陷。本轮不绕过该门禁（不设 `require_stability=False`、不伪造 Oracle 绑定）。

"审核成功 → 执行 → 诊断 → 探针 → 修复 → 晋升 → 回滚"的完整成功路径由两轮闭环脚本验证，
每轮 86/86 API 检查通过，含 Oracle 绑定、稳定性回放与真实人工审批：
- `docs/assets/run011-r1.1/lineage/loop1.json`
- `docs/assets/run011-r1.1/lineage/loop2.json`

## 5. 结论

WP6 UI 验收覆盖了四角色登录、权限菜单、401/403、CRUD 写入的服务端落库校验与审核门禁，
15/15 检查通过且每项均带服务端回读证据。剩余两项（workspace 切换控件、审核成功路径）
