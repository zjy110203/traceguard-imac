## 一、完整执行链路（第 9 条）：入口 → 报告

### 环节 0：启动与配置
- 入口：`main()` → `asyncio.run(run_missions())`（`main.py:746-750`）。
- 解析 CLI 参数（`main.py:161-193`）：`--missions`、`--pr-url`、`--execute`、`--headed`、`--max-steps`(默认30)、`--provider`、`--quiet`、`--regression`、`--export-model`、`--visual`、三种清理开关等。
- 加载配置：`load_app_config()`（`config.py:97`）读取 `APP_CONFIG` 或 `./config.yaml`，用 `_interpolate()`（`config.py:45`）展开 `${ENV}`；`load_environment()`（`config.py:29`）从 cwd `.env` 加载。
- 早期凭证探测：`make_llm(temperature=0)`（`main.py:215`、`utils/llm.py:125`），失败即抛 `ValueError`。
- `--visual` 时启动 Streamlit 子进程并打开 localhost:8501（`main.py:220-277`）。

### 环节 1：任务来源（三条入口）
1. YAML：`yaml.safe_load` 读取 `missions` 列表（`main.py:288-291`）。
2. PR：`--pr-url` → `parse_pr_url()` → `fetch_pr_data()` → `generate_missions_from_pr()`，先写 `missions/pr_<n>.yaml`，`--execute` 时才并入执行（`main.py:293-324`；`pr_analyzer.py:84,340,533`）。
3. 回归/导出：`--regression` 调 `generate_regression_missions()`（`main.py:388-403`；`memory.py:586`）；`--export-model` 调 `export_app_model()`（`main.py:366-386`；`memory.py:626`）。
- 校验：至少一种任务来源，且必须配置 `cfg.app.url`（`main.py:279-284`）。

### 环节 2：初始化会话资源
- 加载 MCP 工具 `get_mcp_tools()`（`main.py:413`；`custom_tools.py:43`）与 Skills 工具 `fetch_agent_skill`、`run_agent_skill_script`（`main.py:414`）。
- `base_tools = doc_tools + skill_tools`（`main.py:454`）——**刻意不含原始 Playwright 工具**。
- `async with` 同时打开：`async_playwright()`、`AsyncSqliteSaver("agent_memory.sqlite")`（checkpoint）、`AsyncSqliteStore("agent_memory.sqlite")`（长期记忆）（`main.py:434-438`）。若配置 embedding 则建索引 `{"dims":..., "embed":...}`（`main.py:427-432`）。
- 启动 Chromium（`headless=not args.headed`）、context（可选 `auth.json` 的 storage_state、忽略 HTTPS 错误、默认超时 5s/导航 15s）、`active_page`（`main.py:439-449`）。

### 环节 3：图构建与 Agent 选择
- 一次编译两套 app（`main.py:456-459`）：`build_graph()`（standard，3 persona）与 `build_advanced_graph()`（advanced，4 persona + explorer）。
- 每个 mission 按 thread_id 关键词选图（`main.py:465-467`，`ADVANCED_KEYWORDS` 见 `main.py:43-53`）：含 `accessibility/a11y/data_heavy/data-heavy/impatient/returning/explorer/chaos/autonomous` → advanced，否则 standard。
- 设 `run_config={"configurable":{"thread_id": thread_id}}`，`aget_state` 判断是否续跑；无历史则注入 `initial_state`（`messages=[HumanMessage(prompt)]`、`next_agent=""`、`step_count=0`、`action_tape=[]`、`bugs_found=[]`、`explored_paths=[]`）（`main.py:494-506`）。

### 环节 4：浏览器会话与页面观察
- 所有 Agent 共享同一个 `active_page`（`standard_graph.py:53-55`、`advanced_graph.py:61-63` 用同一 page 构造工具工厂）。
- 观察手段：`get_dom_snapshot()`（`engine.py:508`）→ `extract_dom_snapshot()`（`engine.py:172`）：**优先** `page.accessibility.snapshot(interesting_only=True)` 并 `_flatten_ax_tree()`（`engine.py:145`）；异常回退 JS DOM walk `_DOM_SNAPSHOT_JS`（`engine.py:80`，跳过 script/style/svg 等 `_SKIP_TAGS`）；`_format_snapshot_for_llm()`（`engine.py:215`）截断为 ≤80 元素的可读文本返回给 LLM。

### 环节 5：动作生成与执行（ReAct 循环）
- Worker 是 `create_agent(llm, tools=..., system_prompt=...)`（`standard_graph.py:91`、`advanced_graph.py:102,119`），system_prompt 由 `make_browser_agent_prompt()` + `BROWSER_AGENT_RULES`（`graph_base.py:24-54`）构成，强制："你是大脑不是手"、"仅通过 execute_browser_command 发 JSON 意图"、"先 get_dom_snapshot"、"禁止 XPath/nth-child/nth-of-type"。
- `make_agent_node()`（`graph_base.py:404`）内部用 `agent.astream()` 实时打印 THOUGHT/ACTION/OBSERV；调用前 `_sanitize_messages_for_model()`（`graph_base.py:378`）丢弃 `SystemMessage`/`ToolMessage` 并将历史规整为纯文本，规避 Anthropic 适配器报错。
- 意图执行 `execute_browser_command(command_json, config)`（`engine.py:420`）：
  1. `json.loads` 解析，必须 Mapping；`action` 必须在 `ALLOWED_ACTIONS`（`engine.py:253`）。
  2. `_validate_selector()`（`engine.py:326`）拒绝脆弱 selector。
  3. `_dispatch(page, action, params)`（`engine.py:363`）执行 11 类动作（navigate/click/fill/press/select_option/hover/wait_for/scroll/extract_text/snapshot/check_page_health）。
  4. 再次 `extract_dom_snapshot()`，`ExecutionResult`（`engine.py:338`）记录耗时/结果/错误/快照。
  5. `_append_tape(thread_id, entry)`（`engine.py:58`）写内存 `_ACTION_TAPES` 与 `report_<thread>/action_tape.jsonl`。
  6. 返回 `STATUS/ACTION/DURATION_MS/RESULT|ERROR/DOM_SNAPSHOT` 文本（`engine.py:488-500`）。

### 环节 6：图循环与 Supervisor 路由
- `compile_swarm()`（`graph_base.py:630`）边：`entry=Supervisor` → 各 agent → `Summarizer` → `Supervisor`；`Supervisor` 条件边按 `state["next_agent"]` 路由，`FINISH`→`END`。
- `make_supervisor_node()` 的 `supervisor_node()`（`graph_base.py:491`）：`step_count+1`；> max_steps 注入 reset 指令并归 1（`graph_base.py:492-511`）；可选 `format_memory_context()`（`memory.py:180`）；`_build_routing_context()`（`graph_base.py:318`）拼装有界简报；`routing_llm.ainvoke()` 结构化输出 `{"next":...}`（`graph_base.py:543-547`）。
- `make_summarizer_node()`（`graph_base.py:574`）：消息 > `keep_recent+1`（默认20）时用 `RemoveMessage` 删除中间消息、替换为紧凑文本摘要，**不调用 LLM**（`graph_base.py:582-621`）。

### 环节 7：结果记录与报告
- 流式事件：`app.astream(..., stream_mode=["updates","messages"])`（`main.py:517-521`）。`updates` 分支写 `STATE UPDATE FROM: <node>` 与各消息 `pretty_repr()`（`main.py:546-558`）；`messages` 分支按 message id 去重、跳过 `AIMessageChunk`/`SystemMessage`，写 `[node] ClassName` + 完整表示到 `report_<thread>/traces.log`（`main.py:559-597`）。
- 报告：`aget_state` 取最终态，`dedupe_bugs()` 去重（`main.py:620-622`）；transcript 逐条裁剪至 2000 字符后 `_bound_transcript_for_report()` 头尾保留（上限 35,000，`main.py:55,68,624-636`）；LLM（可用 `CLAUDE_REPORT_MODEL`/`GEMINI_REPORT_MODEL`）按四段式指令生成 Markdown（`main.py:638-690`）。
- 产物追加 Action Tape 摘要与"可用 `npx playwright test` 运行 `reproduction_*.spec.ts`"提示（`main.py:713-720`）。
- 写记忆：`write_episode_memory()`（`main.py:694-704`；`memory.py:298`）→ 会话摘要 + Bug Catalog。
- 批后：`update_procedural_memory()`（`main.py:726-733`；`memory.py:495`）做 Langmem prompt 反思。mission 间 `MISSION_COOLDOWN` 默认 5s（`main.py:409,722-724`）。

## 四、机制 3：浏览器操作抽象

四层抽象【源码：`engine.py`】：
1. **JSON 意图**：Agent 输出 `{"action":..., "selector"/"url"/"value"/"key"...}`，唯一执行口 `execute_browser_command(command_json, config)`（`:420`，action 白名单 `:253`）。
2. **确定性执行**：`_dispatch(page, action, params)`（`:363`）把意图映射为固定 Playwright 调用；Agent 无法直接执行任意 Playwright 代码。
3. **Action Tape**：每次调用（无论成功失败）经 `ExecutionResult.to_tape_entry()`（`:349`）追加到内存 `_ACTION_TAPES` 与 JSONL（`:46,58-64`）；`AgentState.action_tape` 仅保留最近 50 条（state 瘦身，全量在磁盘）。**可信度边界**：内存 Tape 为可变 `List`，JSONL 以追加模式写入、失败仅 warn，无哈希链/签名/篡改检测，源码注释的 "immutable" 不构成安全保证；`get_dom_snapshot_tool()`（`:505`）不写 Tape，故 Tape 仅记录浏览器命令，不是完整交互轨迹。
4. **观察轨迹**：`extract_dom_snapshot()`（`:172`）AX 树优先 + JS 回退；`check_page_health`（`:399-407`）用 `_HEALTH_CHECK_JS` 扫错误横幅/spinner，返回 HEALTH 文本——这是唯一的"自动健康信号"，但**属于查询而非独立 Oracle**。

韧性 guard：`_validate_selector()`（`:326`）依据 `_BRITTLE_SELECTOR_PATTERNS`（`:305`）拒绝 XPath、`:nth-child`、`:nth-of-type`、裸 `div/span` 位置链。

## 五、机制 4：Agent 如何发现和记录问题

1. **发现触发**：`BROWSER_AGENT_RULES`（`graph_base.py:24-49`）要求 LLM 把"UI bug/校验错误/缺失元素/视觉异常/无障碍问题/UX 缺口"都计入 issue；失败策略要求先 `capture_bug_screenshot` 再 `generate_reproduction_spec`。
2. **证据落地**：`capture_bug_screenshot(bug_summary, config)`（`custom_tools.py:397`）→ `report_<thread>/screenshots/bug_<safe>_<ts>.png`（full_page）。
3. **结构化记录**：Agent 结束回合前输出 `<bugs_found>[{"title","summary","location","severity"}]</bugs_found>`；`_extract_bugs_from_text()`（`graph_base.py:159`）解析 JSON tag，失败回退到 `_BUG_PROSE_RE` 匹配 `BUG FOUND:/BUG:` 前缀（`graph_base.py:107-114`）。`_extract_bugs()`（`graph_base.py:202`）还读取 `capture_bug_screenshot` 的 `bug_summary` 参数（因 ToolMessage 会丢弃该参数）。
4. **去重**：`_normalize_bug_key()` 取 title（`:`/`.` 之前）+ `_is_dup_key()` 前缀重叠 ≥12 字符（`graph_base.py:117-143`）；`dedupe_bugs()`（`graph_base.py:146`）用于报告。
5. **跨会话编目**：`write_episode_memory()`（`memory.py:298`）→ `catalog_bug()`（`memory.py:260`）以 `_bug_fingerprint`（MD5(page + summary前100)）为键，`seen_count` 累加、`status="open"`，并写入 `recall_past_findings` 可检索。
6. **证据可信度提示**【源码 + 推断】：BUG 的"判定"来自 LLM 自述文本，无独立 Oracle 校验；`check_page_health` 的错误横幅是启发式 DOM 扫描，二者均未交叉验证。

## 六、机制 5：探索结果如何转化为可复现 Playwright 测试

```
Action Tape (JSONL/内存)
   └─ _tape_entry_to_ts(entry)  engine.py:523   # 每条 tape 映射为 TS 语句
        ├─ navigate → page.goto('...')
        ├─ click/fill/press/select_option/hover → 对应 page.* 调用
        ├─ wait_for → page.waitForSelector('...',{state})
        ├─ extract_text → const _t = ...innerText(); expect(_t.length).toBeGreaterThan(0)
        ├─ snapshot / check_page_health → 注释（回放 no-op）
        └─ 失败条目 → 前置 "FAILED AT RECORD TIME ... Error: ..." 注释
   └─ generate_playwright_spec(thread_id, bug_summary, app_url, storage_state_path)
        engine.py:565  → report_<thread>/reproduction_<safe>_<timestamp>.spec.ts
        含 import @playwright/test、test.use({storageState:'auth.json'})、
        test.setTimeout(120_000)、逐条步骤、运行说明注释
   └─ generate_reproduction_spec(bug_summary, config)  engine.py:619  # Agent 可调用的工具
```
- 触发方式：`BROWSER_AGENT_RULES` 指示 Agent 在 `capture_bug_screenshot` 后立即调用（`graph_base.py:32-33`）；工具由 `get_code_generator_tool(app_url)` 注入（`standard_graph.py:55,64`、`advanced_graph.py:63,69`）。
- **局限**【源码】：这是**动作序列回放**，唯一断言是 `extract_text` 的长度>0；`snapshot`/`check_page_health` 在回放中为 no-op；生成的 spec 依赖 `auth.json` 存在（default `storage_state_path="auth.json"`，`engine.py:569`），且无"Bug 是否重现"的验证断言。

## 七、机制 6：如何实现测试复现

- 手工复现：在 `report_<thread>/` 下运行 `npx playwright test <spec> --headed`（spec 头部注释给出，`engine.py:586-604`；报告提示见 `main.py:719`）。
- 断点续跑：相同 `thread_id` 再次运行会从 checkpoint 恢复（`missions/README.md:17-21`；`main.py:494-498`）。
- 语义回归：`--regression` 从 Bug Catalog 生成针对已发现 bug 页面的新 mission（`memory.py:586-619`；`main.py:388-403`），并给 Agent `recall_past_findings` 工具获取上下文。
- 失败恢复：LLM 暂态错误重试（max_retries=5，指数退避；rate-limit 30s+）（`main.py:508-617`）。
- **注意**：ATE 的"复现"指**重放探索动作序列**；是否真正复现缺陷依赖人工执行 spec 观察，框架本身不判定复现成功与否【源码 + 推断】。

## 九、TraceGuard 初步映射小结（仅标注）

| ATE 环节 | 对应 TraceGuard 概念 | 差异提示 |
|---|---|---|
| 环节 4/5 的 DOM 快照 + JSON 意图执行 | Explorer Agent + Playwright 确定性执行 | ATE 已实现 Brain/Hands 分离 |
| Action Tape / traces.log | Exploration Trace / Event/Evidence | ATE 为消息级与动作级原始日志，非语义化事件图 |
| 环节 6 的 Tape→spec.ts | TestCase Compiler | ATE 是线性翻译，缺语义编译与断言 Oracle |
| 环节 7 的 `_extract_bugs` / `catalog_bug` | Diagnosis / Diagnosis 记忆 | ATE 为 LLM 文本抽取，无因果诊断 |
| `check_page_health` / `analyze_visual_state` | Trusted Oracle | **ATE 无独立 Oracle**；视觉判定工具未接入默认图 |
| `prioritize_pages` / `recall_past_findings` | Evidence Graph 查询 / Active Diagnosis Planner 输入 | ATE 为 KV + 检索，非图；无规划闭环 |
| — | RepairProposal / UI-FaultBench | ATE 源码中**不存在**对应实现 |
