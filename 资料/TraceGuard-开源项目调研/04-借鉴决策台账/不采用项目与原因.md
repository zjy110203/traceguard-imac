# 不采用项目与原因

- 说明："不采用"指不引入为依赖、不复制源码；不影响"学习其设计思想"。
- 分类：① 硬约束不采用（许可证/架构冲突）；② 当前不采用（与 v1.1 设计重复或边界不符）；③ 条件性不采用（待确认项未通过前不引入）。
- 所有结论为候选意见，须评审；不采用 ≠ 项目质量差。

## 一、硬约束不采用

| 项目 | 不采用类型 | 原因 | 可否学习设计 |
|---|---|---|---|
| TestZeus Hercules | 许可证硬约束 + 架构冲突 | **AGPL-3.0 强 copyleft；第 13 条仅针对"修改后的程序支持网络远程交互"情形，需向远程用户提供修改版对应源码，不能泛化为所有 SaaS 使用都自动公开整个平台源码**。若在 TraceGuard 中复制/修改其代码并对外提供修改版，才触发相应披露义务（需逐案法律评估）。且无独立 Assertion Agent、Planner 自报 is_passed 判定（弱证据、False Pass 风险）、playwright<=1.49 旧锁定。决策状态"不采用/待法律评估" | 可：Planner 结构化计划、AgentRegistry、报告产物组织、失败分类（独立重实现，不复制代码） |
| Neo4j | 许可证约束（条件性）+ 非必需 | 社区版 GPL-3.0（**无 AGPL 第 13 条网络交互条款**；义务主要在复制/修改/分发/组合时产生，内部运行或独立服务/API 调用通常不自动触发源码披露），企业版闭源需商业授权；v1.1 首期明确用 PostgreSQL 关系表实现 Evidence Graph，P12 图数据库必要性未定。当前不引入 | 可：属性图建模、Cypher 多跳查询思想（P12 通过后评估） |

## 二、当前不采用（与 v1.1 设计边界不符）

| 项目 | 不采用类型 | 原因 | 保留的借鉴价值 |
|---|---|---|---|
| Temporal | 不替换既定设计 | v1.1 已定 Celery + Redis + PostgreSQL 租约/执行代次方案；引入 Temporal 等于替换核心执行架构，违反任务约束。任务书明确"仅作工作流编排研究参考" | Event History、声明式 Retry、Durable Execution 思想 |
| OWASP ZAP | 职能边界不符 | 安全扫描器，alerts 是潜在漏洞，不判定 UI 功能/视觉/交互正确性；主动扫描属攻击须授权。不能当 UI 测试诊断或 Evidence 直接来源 | 被动采集 + REST/Automation Framework 集成思想（用于阶段 12 安全测试参考） |
| OWASP Juice Shop | 用途边界 | 安全培训/CTF 靶场，不是通用 UI 测试套件；部分挑战依赖外部 AI/LLM，Danger Zone 默认禁用 | 作为阶段 1/12 受控应用与场景设计样例（独立部署，不作为产品依赖） |
| ReportPortal | 与自建设计重复 | v1.1 已有自建工作台、Event/Evidence、Diagnosis；ReportPortal 的失败分类是打标，非根因诊断。直接引入会与既有模块边界重叠 | Launch/Test Item 层级、历史签名、Automatic Analysis 思想 |
| Allure Report | 自建报告优先 | v1.1 有自建报告/工作台；引入外部报告框架须先论证"现有模块为何不能承担"（冻结原则 PRJ-18 第 2 条）。当前不列为新增 A 类 | 结果数据文件与展示解耦、JUnit/Attachment 结构 |
| Langfuse | 数据模型边界 + 混合许可 | LLM Agent Trace ≠ 业务 Testing Evidence（任务书明确边界）；核心 MIT 但 `ee/` 为商业许可，复制有合规风险 | LLM 语义 trace + OTel 底座、Dataset/Experiments 评测（仅设计层） |
| BrowserGym | 平台职能边界 | Web Agent 研究/评测环境，"not meant to be a consumer product"；不是测试管理/诊断平台 | AbstractBrowserTask 任务抽象、Episode/Reward、Action Space |
| AgentLab | 平台职能边界 | Web Agent 评测与实验管理，不提供 UI 故障诊断；对需 reset 的 benchmark 不支持跨实例并行 | Study/复现日志/AgentXray 的实验管理思想 |

## 四、反面案例（用于设计评审，不作为任何采用候选）

| 项目 | 反面教训 |
|---|---|
| Agentic Test Explorer | 无独立 Oracle、LLM 自报 PASS/FAIL、spec 回放仅含弱检查（`toBeGreaterThan(0)`）、无目标缺陷/业务预期的有效验证断言 —— 印证"Oracle 必须独立""探索轨迹≠测试" |
| TestZeus Hercules | `_assertion_node` 信任 Planner 自报 is_passed、默认配置关闭多处证据能力 —— 印证"确定性 Verdict 不可由 Agent 自报" |

## 五、不采用结论的边界声明

1. 不采用某项目，不代表否定其工程质量；判断基于与 TraceGuard v1.1 架构、可信边界、许可证的兼容性。
2. "可学习设计"与"可引入代码"是两件事：本报告对多数不采用项目仍保留设计层借鉴价值。
3. 条件性不采用项目在对应确认项（P01/P02/P12 等）通过后，可重新进入评审。
