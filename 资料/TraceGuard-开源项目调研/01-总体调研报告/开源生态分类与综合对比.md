# 开源生态分类与综合对比

- 用途：按 TraceGuard 能力方向对 19 个项目分类，提供跨项目综合对比视图。
- 依据：各项目官方核实（R1）+ 两个重点项目源码级研究（R1）。
- 纪律：维护情况依据真实 commit/release 日期，不主观判断；功能依据官方资料与源码，不编造。

## 四、关键观察

1. **没有单一开源项目覆盖 TraceGuard 全链路**：每个项目只覆盖能力谱的一段，印证 TraceGuard 需要自建整合架构，不能靠引入某个项目替代。
2. **Agentic Testing 类（ATE/Hercules）在"判定"上各有形态，但共同缺少独立 Oracle**：ATE 主要依赖 LLM 对探索结果做缺陷分析并自报 PASS/FAIL，缺少独立可信 Oracle；Hercules 没有独立 Assertion Agent，最终 `is_passed` 仍由 Planner 提供，但具有默认注册的 API 确定性断言 `assert_json_path`、opt-in 的 UI 断言 `assert_ui` 和报告期断言账本覆盖机制。二者共同缺少 TraceGuard 要求的独立 Trusted Oracle、可信预期来源绑定与完整确定性 Verdict——反向印证冻结原则的价值。
3. **证据/诊断类项目不与测试执行打通**：OpenTelemetry/Langfuse 做可观测，ReportPortal 做结果分析，但都不提供"UI 测试证据→多假设诊断→受控探针"闭环，这正是 TraceGuard 差异化所在。
4. **自愈类项目缺少安全边界**：Healenium/Hercules healing 都不含 Oracle 保护、断言保护、审批与回归门禁——TraceGuard 的 Oracle-Protected Self-Healing 需自建。
5. **Benchmark 类可借鉴组织方式但非评测对象本身**：Inspect AI/AgentLab/BrowserGym 提供评测框架与实验管理，TraceGuard 的 UI-FaultBench 需按其业务指标自建。
