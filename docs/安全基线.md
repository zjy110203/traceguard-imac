# TraceGuard 安全基线（阶段0）

## 1. 凭据与配置

- 所有配置通过 `TG_` 前缀环境变量注入；`.env` 被 `.gitignore` 排除。
- 代码中读取的敏感字段（password/secret/token/key/credential）在日志与 `public_dict()` 中自动遮蔽（`traceguard_core.logging.redact`）。
- Docker Compose 使用 secrets 文件，不写明文口令；`infra/secrets/` 不入库。
- 未发现真实凭据；仓库仅含 `*.example` 示例文件。
- 禁止提交密钥；CI 未配置任何真实外部服务凭据。

## 2. 文件与路径边界

- 应用数据写入项目内 `.traceguard/`（SQLite）与 `logs/`、`tests/reports/`，均在仓库内。
- 不读取项目外文件；测试用 `tmp_path` 隔离。
- Evidence 附件大小上限由 `TG_MAX_UPLOAD_BYTES` 约束（默认 10MB）。

## 3. 网络与浏览器（阶段0 预留，后续启用）

- 平台 API 绑定 `127.0.0.1`，不对外网卡暴露。
- CORS 白名单 `TG_ALLOWED_ORIGINS`，默认仅本机前端。
- SSE 仅作展示通道，不作为权威状态来源。
- 外部 Web 应用访问需明确授权（阶段12 前保持 BLOCKED）。
- 浏览器隔离、SSRF/DNS Rebinding/Redirect 防护、Prompt Injection 防护在阶段4/5/12 落实，不在阶段0 虚构。

## 4. 数据与所有权

- PostgreSQL（本机为 SQLite 降级）是业务状态唯一权威来源；Redis 不作第二套业务库。
- 每个业务对象唯一写入模块（见 `资料/项目资料/04` 数据所有权表）。
- Agent 不直接写权威状态、不批准 Oracle、不自批 Repair。

## 5. 审计基础

- 结构化 JSON 日志含时间戳、级别、logger、event 字段。
- 统一错误码（`traceguard_core.errors.ErrorCode`），错误响应不泄露堆栈细节给客户端。
- 管理/敏感操作的完整审计在后续阶段随权限模块落地。
