# TraceGuard 确定性执行内核（阶段2）

## 1. 组成

| 模块 | 文件 | 职责 |
|---|---|---|
| TestCase 加载器 | `traceguard_execution/testcase/loader.py` | 加载不可变 TestCaseVersion，校验必需断言集 |
| Oracle Manager | `traceguard_execution/oracle/manager.py` | 来源/审批校验，可用性检查；冲突检测（不裁决，P03 待确认） |
| Assertion Evaluator | `traceguard_execution/runtime/assertions.py` | 基于观测 + Oracle 规则确定性判定四态 |
| Verdict 聚合器 | `traceguard_execution/verdict.py` | 已冻结四态聚合规则 + 8 补充规则 |
| Observer 协议 | `traceguard_execution/runtime/observer.py` | 统一观测接口 |
| HttpObserver | `traceguard_execution/runtime/http_observer.py` | 真实 HTTP 确定性观测（降级路径，mode=http-fallback） |
| PlaywrightObserver | `traceguard_execution/runtime/playwright_observer.py` | 真实浏览器执行（首选路径，mode=playwright） |
| LocalExecutor | `traceguard_execution/runtime/orchestrator.py` | 本地同步编排：加载→执行→断言→Verdict→Run 报告 |

## 2. 关键不变式（已由测试验证）

1. Oracle 不可用 → NOT_EVALUATED，**永不 PASSED**（`test_oracle_unavailable_never_passes`）。
2. 空必需断言集 → 拒绝（ValueError），不自动 PASSED（`test_empty_required_assertions_rejected`）。
3. 必需断言失败 → FAILED，不因执行中断被掩盖（`test_failed_not_masked_by_interruption`）。
4. 未完成执行 → 即便已完成断言通过也只判 INCONCLUSIVE（`test_incomplete_execution_not_passed`）。
5. Optional 断言不决定 Verdict（`test_optional_failure_does_not_decide`）。
6. execution_status 与 test_verdict 独立（`test_execution_status_independent_of_verdict`）。
7. Trusted Oracle 业务状态在**所有操作步骤之后**查询（`test_db_false_pass_detected` 揭示旧时序 bug 已修复）。

## 3. Trusted Oracle 路径

TF-DB-001 场景下，UI 显示"创建成功"但数据未持久化：
- UI 断言（banner-success）：PASSED
- 业务状态断言（`/api/state/projects` count==1）：FAILED
- 整体 Verdict：FAILED（揭穿 False Pass）

业务状态查询独立于 UI 与 Agent，直接读 TeamFlow 持久层。

## 4. 两条 Observer 路径的区别（不得混淆）

| 路径 | mode | 说明 |
|---|---|---|
| PlaywrightObserver | `playwright` | 真实浏览器渲染、截图、网络事件；阶段2 首选 |
| HttpObserver | `http-fallback` | 真实 HTTP + HTML 文本解析；无真实浏览器渲染；本机网络受限时的降级 |

Run 报告明确记录 `observer_mode`。**降级路径的报告不得冒充真实浏览器 E2E。**
两条路径共享同一 Verdict 聚合逻辑，保证判定标准一致。
