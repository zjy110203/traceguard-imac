| 主要语言 | TypeScript（约 798 万字节），MDX、Python、Go 等多语言 SDK | languages API |

| 最近维护 | 主仓 commit 2026-11-18（SHA 8901460）；最新 release 为组件 server-v3 v3.7.7 / 2026-10-23 | commits API；releases/latest |
| 定位 | "The SDK to extract data and interact with any site on the web." | README |

**核心机制**（三大 API，来源 docs.stagehand.dev/v4）：
- `act()`：每次执行**单个**动作；接受自然语言或 `observe()` 返回的 `Action`（**零推理确定性重放**）；官方强调多步指令不可靠，需自行拆分。
- `observe()`：发现页面上可操作元素，返回结构化 `Action`（含 selector / description / method / arguments），可执行前校验、缓存。
- `extract()`：带指令 + 输出结构（TS 用 Zod、Python 用 Pydantic、Go 用类型推导 JSON Schema）抽取结构化数据，返回前按 schema 校验。
- AI+确定性结合：Action 重放跳过推理；selector/locator/ignoreLocators 限定范围；variables 防密值入提示；Browserbase 服务端缓存；`observe/act` 默认合并每 frame 的 accessibility tree，处理 iframe 与 shadow DOM。

**未核实/注意**：文档为 v4，与 v3（基于 Playwright）差异显著；v4 不提供 Playwright/Puppeteer page interop，"Playwright 风格"仅指 locator 写法体验；latest release 是 server-v3 组件版本，非 v4 SDK 版本；服务端缓存仅对 Browserbase 浏览器有效。

**核心机制**（来源 playwright.dev docs + README）：

- Test Runner/并行/重试：worker processes 各自启动浏览器，按文件并行，fullyParallel/workers/sharding 可配；重试默认关闭，失败分 passed/flaky/failed。

| 字段 | 核实结果 | 来源 |

| License | **Apache-2.0** | /blob/main/LICENSE |
| 主要语言 | 规范文档仓库，主体为 Markdown（languages API 仅显示 Makefile） | languages API |
| 技术栈 | 跨语言 OTel 规范（API/SDK、OTLP、语义约定）；注意 Collector 实现在独立仓库 opentelemetry-collector | 仓库页；opentelemetry.io/docs/collector |

| 定位 | "describes the cross-language requirements and expectations for all OpenTelemetry implementations" | 仓库页 |

**核心机制**（来源 opentelemetry.io/docs/specs/otel）：
- Trace/Span：Span 表示 trace 内单一操作，可嵌套成树，每 trace 单一 root；`TracerProvider→Tracer→Span`。
- Event：由 name、timestamp、零或多个 Attributes 构成；RecordException 为特化变体。
- Context Propagation：跨 API 边界传播执行作用域值，不可变；SpanContext 遵循 W3C TraceContext（TraceId 16 字节、SpanId 8 字节、TraceFlags、TraceState）。
- Attribute：key-value 对；可配 AttributeCountLimit(默认128)/ValueLengthLimit/DepthLimit。
- Resource：被观测实体的不可变表示，由 Entities + Attributes 组成。
- Collector：厂商中立的接收/处理/导出实现，含 receivers/processors/exporters/connectors/extensions（独立组件/仓库）。
**注意**：规范中大量字段标注 Stable/Development/Mixed（如 Entity 为 Development），采用时逐字段核对。

- Workflow Execution：durable function 的运行时；每次执行独占本地状态、并发运行、经消息传递通信；执行一次并完成，无论耗时。

- Retry：声明式；默认 Initial Interval 1s、Backoff 2.0、Max Interval 100×初始、Max Attempts ∞、Non-Retryable Errors []；Activity 默认重试，Workflow Execution 默认不重试。
- Timeout：retry 文档出现 Workflow Execution Timeout、Schedule-To-Close Timeout、Workflow Task Timeout；**各类 timeout 完整官方定义页 404，未核实**。
- Durable Execution：通过 Event History 记录每步状态，失败后从最后事件恢复，不丢进度。
**注意**：Temporal 仅作工作流编排研究参考，不等于替换 TraceGuard 原有 Celery 设计。
