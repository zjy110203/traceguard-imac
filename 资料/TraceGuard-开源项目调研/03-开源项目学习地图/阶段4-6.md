# TraceGuard v1.1 团队学习路线：阶段 4–6

## 本阶段区间定位

本册覆盖 v1.1 的证据基础设施与两类核心 Agent 能力（阶段 4～6）：阶段 4 建立 Event 与 Evidence 分离的统一底座，明确"Agent 是能力层不是事实层"的数据前提；阶段 5 让 Explorer Agent 在 Playwright 之外的浏览器 Agent 辅助下自主探索并产出 Exploration Trace；阶段 6 由 TestCase Compiler 把轨迹转写为可审核、可独立回放、带可信 Oracle 绑定的 Candidate TestCase。三者串成"可观测事实 → 探索轨迹 → 可测试资产"的主链。必须牢记：本区间只产出候选，不宣布测试通过；Langfuse 的 LLM Trace 不进入业务 Evidence；Playwright 仍是确定性执行内核，Browser Use 只作探索能力层。

> 角色简称（职能分工，非新增概念）：平台工程师（工程基座/CI/编排/部署）、执行内核工程师（Playwright + pytest）、Agent 工程师（Explorer/Compiler/Diagnosis/Planner/Repair）、证据工程师（Event/Evidence/Graph/PostgreSQL）、评测工程师（UI-FaultBench/指标）、安全工程师（安全基线/Tool Gateway/ZAP/可靠性）、工作台工程师（Vue 工作台/FastAPI/可视化）。
> 阶段名称严格采用 v1.1 正式名称；边界口径与《TraceGuard 十四阶段开源项目映射》《指定项目官方信息核实记录》一致。

### 阶段 4：Event 与 Evidence 证据基础设施

**推荐学习内容**

1. OpenTelemetry Trace/Span/Event/Context：W3C TraceContext、Attribute 与 Resource
2. Langfuse LLM Trace 数据模型（built on OTel），及其与业务 Evidence 的区别
3. Event 幂等：Outbox/Consumer Inbox、`context_refs` 绑定与序号缺口检测
4. Evidence 分层：原始证据不可变、派生保留来源、SHA-256、脱敏/检索/过期清理

|---|---|---|---|---|---|---|---|

**边界纪律**：Event 与 Evidence 分离；Langfuse LLM/Agent Trace ≠ TraceGuard 业务 Testing Evidence，不照搬其 Enterprise 许可 `ee/` 代码；不把 `trace_id`/`request_id` 当因果依据；不为满足 `workspace_id` 虚构归属。

**学习成果**：能够理解并参与 TraceGuard Event 与 Evidence 证据基础设施的开发，并守住"事实层"的可信边界。

### 阶段 5：Explorer Agent 自主 Web 探索

**推荐学习内容**

1. Browser Use 页面观察与 REPL + CDP 架构（1.0：model + REPL + CDP）
2. Stagehand `observe()/act()/extract()` 与"先校验再执行"
3. ATE 多 Agent 探索与 Brain/Hands 分离（JSON 意图 + 确定性 dispatch）
4. LangGraph StateGraph：State/Node/Edge/条件边
5. Agent State 与 Checkpoint：短期状态与恢复，PostgreSQL 才是业务状态权威
6. 浏览器操作记录：Action Tape 与 Exploration Trace 结构
7. Tool Gateway：权限、域名、预算与越权拦截
