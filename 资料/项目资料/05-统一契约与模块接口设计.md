# TraceGuard 统一契约与模块接口设计

-   架构基线：v1.1
-   状态：C01～C12 契约地图；正式字段和 JSON Schema 待逐项冻结
-   说明：本文不替代最终 Schema 文件。

## 1. 契约设计目标

C01～C12 定义模块之间交换的数据结构、状态、方法、异常和 Mock 场景。

契约不仅是字段列表，还需要明确生产者、消费者、所有者、交互方式、成功条件、失败条件、重试、幂等、兼容版本和验证方法。

## 4. 各契约职责

### C01：TestIntent Contract

定义意图标识、需求描述、需求来源、业务对象、前置条件、候选场景、候选
Assertion、审核状态、版本和追溯关系。

约束：AI 生成的候选内容不能自动成为正式验收标准。

### C02：TestCase Contract

定义 TestCase 与
TestCaseVersion、测试步骤、Locator、操作参数、Assertion、测试数据、前置条件、后置条件、清理策略、运行配置、编译来源、审核和晋升状态。

约束：正式版本不可原地覆盖；历史 Run 绑定具体版本。

### C03：Oracle Contract

定义 Assertion 级 Oracle、预期行为、需求来源、审核记录、Primary
Oracle、Supporting Oracles、Evaluation
Rule、一致性等待窗口、必需断言标记、版本和快照。

约束：Primary Oracle 按 Assertion 指定，不建立全局固定优先级。Oracle
不可用不能解释为通过。

### C04：Execution Contract

定义
Task、Run、Step、任务调度、执行配置、状态转换、超时、取消、重试、结果和资源引用。

约束：Task 是逻辑任务，Run 是执行尝试；重试不覆盖历史 Run。

### C05：Event Contract

建议统一 Event Envelope：

``` json
{
  "event_id": "evt_001",
  "event_type": "network.request.failed",
  "schema_version": "1.0.0",
  "run_id": "run_001",
  "step_id": "step_003",
  "producer_id": "playwright_runner",
  "producer_instance_id": "runner_instance_001",
  "sequence": 15,
  "occurred_at": "2026-11-17T00:00:00Z",
  "recorded_at": "2026-11-17T00:00:01Z",
  "idempotency_key": "run_001:runner_instance_001:15",
  "correlation_id": "req_001",
  "payload": {}
}
```

示例仅说明语义，不是冻结 Schema。

约束：至少一次投递 +
消费端幂等；生产者实例内序号；发生时间和接收时间分开；不承诺全局严格顺序；支持重试、重放和死信；持久化后再用于可靠展示。

### C06：Evidence Contract

定义 Evidence
ID、类型、原始或派生标记、来源、Run/Step、时间、内容摘要、附件引用、完整性、来源可信度、派生关系、脱敏状态和保留策略。

约束：`integrity_check` 与 `source_trust`
分开。派生证据不能被重复计算为独立原始证据。

### C07：Evidence Graph Contract

节点建议：Run、Step、Event、Evidence、Assertion、Hypothesis、ProbeExecution、Source。

边建议：parent_child、emitted_by、derived_from、correlated_by_trace_id、correlated_by_request_id、same_execution_context、temporal、supports、contradicts、evaluates。

约束：边必须有明确起点、终点、关系类型和来源依据。关联不等于因果。

### C08：Diagnosis Contract

定义 Diagnosis、Diagnosis Status、Diagnosis
Outcome、Hypothesis、支持证据、反驳证据、诊断策略版本、探针历史、停止原因和未解决冲突。

约束：允许多根因；允许 PROBABLE 和 INCONCLUSIVE；不允许无证据强制确定。

### C09：Probe Contract

定义 Probe ID
和版本、能力描述、输入参数、目标范围、权限要求、风险等级、是否只读、副作用、超时、预算、执行结果、失败原因和产生的
Evidence。

约束：权限检查优先于评分；ProbeExecution 失败不等于目标故障成立。

### C10：Disposition Contract

定义处置对象、诊断引用、故障类别、处置建议、路由目标、审核状态和处置结果。

约束：Diagnosis 与 Disposition 分离；处置不能覆盖诊断原始结论。

### C11：Repair Contract

定义 RepairProposal、原始 TestCaseVersion、Diff、影响范围、Assertion
Preservation 结果、Sandbox Validation、Approval 引用、Regression
引用、晋升版本和回滚记录。

约束：修复提案生命周期与沙箱验证状态分开；正式晋升需要满足策略和审批条件。

### C12：Benchmark Contract

定义 Dataset、Dataset
Version、BenchmarkCase、GroundTruth、Experiment、Experiment
Run、Baseline、Evaluation
Metric、EvaluationResult、数据集划分和模型配置快照。

约束：Ground Truth 与被测 Agent
隔离；测试集按故障机制、场景变体和应用版本防止泄漏。

## 5. 模块交互方式

  --------------------------------------------------------------------------
  方式                    适用场景                   示例
  ----------------------- -------------------------- -----------------------
  同步服务接口            需要立即获得结果或校验     创建 Task、读取 Oracle

  异步命令 / 任务         长时间执行                 执行 Run、启动
                                                     Diagnosis

  领域事件                状态变化通知和跨模块消费   Run Completed、Evidence
                                                     Created
  --------------------------------------------------------------------------

不要把所有模块通信都做成同步
HTTP，也不要把所有调用都改成事件。应根据一致性、延迟、恢复和调用方需求选择。

## 6. 统一接口规范

每个接口至少说明： - 接口名称和用途； - 调用方和被调用方； -
请求结构； - 响应结构； - 权限要求； - 幂等要求； - 超时； -
重试策略； - 错误码； - 状态副作用； - 事件副作用； - 契约版本； - Mock
和测试用例。

## 7. 错误分类建议

  类别                   示例
  ---------------------- ------------------------
  VALIDATION_ERROR       字段缺失、格式错误
  AUTHORIZATION_ERROR    权限不足
  NOT_FOUND              对象不存在
  CONFLICT               版本冲突、状态不允许
  PRECONDITION_FAILED    前置条件不满足
  RESOURCE_UNAVAILABLE   浏览器或 Worker 不可用
  TIMEOUT                执行超时
  RATE_LIMITED           资源或调用频率受限
  DEPENDENCY_ERROR       外部依赖失败
  INTERNAL_ERROR         未预期内部错误

具体错误码命名、HTTP 状态映射和重试属性待统一冻结。

## 8. 版本与兼容策略

-   每个契约有独立版本；
-   事件包含 schema_version；
-   破坏性变更升级主版本；
-   新增可选字段优先保持兼容；
-   消费端对未知字段的处理策略明确；
-   历史对象保留创建时使用的契约版本；
-   数据迁移应有可回滚策略。

## 9. 契约验收清单

每份 C01～C12 至少提供字段表、JSON
Schema、合法样例、非法样例、联合约束、状态转换约束、请求和响应
Mock、错误码、兼容性说明和契约自动化测试。
