# C01～C12 契约治理规范（阶段0）

## 权威来源与派生关系

- **权威来源**：`packages/contracts/traceguard_contracts/` 下的 Pydantic 模型。
- **派生产物**：`packages/contracts/schemas/*.schema.json`（由 `export_schemas.py` 导出，draft 2020-12）。
- 修改契约字段必须先改模型 → 重跑导出 → 更新生产者/消费者 → 更新契约测试 → 升版本。禁止直接改 schema json。

## 每份契约交付清单（路线图 05 第9节）

| 项目 | 状态 |
|---|---|
| 对象定义与字段类型 | 模型已定义 |
| 必填/可选约束 | Pydantic Field 约束 |
| 枚举 | common.py 枚举类 |
| JSON Schema | 导出脚本生成（draft 2020-12） |
| 合法样例 | 见 `tests/contracts/test_contracts.py` 内构造 |
| 非法样例 | 同上（extra 字段/空断言集/Agent 批准等） |
| 状态转换 | 状态枚举与资料/06 对齐；完整转换表随各阶段细化 |
| 生产者/消费者 | 见 `资料/项目资料/05` 契约总览表 |
| 版本兼容规则 | schema_version 字段 + 破坏性变更升主版本 |
| 错误处理 | `traceguard_core.errors` 统一错误码 |
| 自动化契约测试 | `tests/contracts/` |

## 版本规则

- 当前所有契约 `schema_version = 0.1.0`（初始版本，渐进冻结）。
- 新增可选字段：patch/minor，保持兼容。
- 破坏性字段变更：升主版本，历史对象保留创建时版本。
- 事件始终携带 `schema_version`；消费端对未知字段默认忽略（但权威对象 `extra=forbid`）。

## 已冻结语义（不得违背）

- C02：TestCaseVersion 不可原地覆盖；空必需断言集非法（F05）。
- C03：Oracle 不由 Agent 批准（`approved_by_agent` 恒 False）。
- C04：Run 绑定具体 TestCaseVersion；execution_status 与 test_verdict 独立。
- C05：workspace_id 必填且服务端注入；context_refs 统一关联；（producer_instance_id, sequence）唯一；occurred_at/observed_at 分离（F01/F02/G05）。
- C06：integrity_check 与 source_trust 分离；派生证据记录来源。
- C07：每条边必须有 basis；关联不等于因果。
- C08：仅 CONFIRMED 支持成为 root cause；允许多假设与 INCONCLUSIVE（F04）。
- C09：Probe BLOCKED 不代表目标故障成立；禁任意 SQL（F07）。
- C11：base/candidate/target 版本保护；Agent 不自批自修（F10）。
