# TraceGuard｜RUN-011-R1.1 WP1 多 Workspace 安全验收

- 验收脚本：`tests/integration/test_workspace_isolation_run011_r1_1.py`（9 个用例）
- 执行结果：**9 passed / 0 failed**（SQLite + 认证开启 + CSRF 强制）
- 基线问题：`docs/RUN-011-R1.1-BASELINE.md` §1–§5
- 原则：**实体 Workspace 由服务端数据库行确定；请求体/query 只作为待校验声明**

---

## 1. 账号与数据拓扑

| Workspace | viewer | qa-engineer | qa-lead |
|---|---|---|---|
| `ws-iso-a` | `a_viewer` | `a_engineer` | `a_lead` |
| `ws-iso-b` | `b_viewer` | `b_engineer` | `b_lead` |
| 全部 | `platform_admin`（`roles=platform-admin`, `workspaces=["*"]`） | | |

每个 Workspace 在验收夹具中建立完整主链：Intent → TestCase/Version → Task →
失败 Run → Evidence → Diagnosis → Probe Plan → Repair Proposal。
**没有任何账号使用 `workspaces=["*"]` 参与隔离负向测试**（admin 仅用于正向跨空间对照）。

## 2. 实现要点

| 层 | 修复 |
|---|---|
| `apps/api/traceguard_api/workspace.py`（新增） | `principal_of()` / `require_entity_workspace()` / `scope_filter()` / `filter_by_workspaces()` 统一出口；拒绝时写 `WORKSPACE_FORBIDDEN` 审计 |
| `TaskService.create_task()` | `workspace_id` 必填，空值 fail-closed `WORKSPACE_REQUIRED`；幂等键跨 Workspace 复用报 409 |
| `TaskService.create_run()` | 校验版本存在、属于 Task.testcase_ref、Workspace 与 Task 一致；禁止跨空间 Run |
| `routers/execution.py` | `/tasks`、`/testcases/{id}/execute` 从版本行解析权威 Workspace；12 个 detail/写路由逐实体授权；列表下推 `workspace_ids` |
| `routers/catalog.py` | 写入前校验 Workspace；Intent ID 跨空间复用拒绝；TestCase 跨空间追加版本拒绝；detail/版本/Oracle 对象级授权 |
| `routers/evidence.py` | evidence / event / artifact detail 与下载按实体 Workspace 授权；列表默认作用域 |
| `routers/intelligence.py` | diagnosis / graph / probe / repair 全链对象级授权；伪造 body workspace 不生效 |
| `stores.py` / `catalog.py` | `workspace_ids` 过滤下推到 SQL；`DocStore.put()` 跨 Workspace 覆盖写保护 |
| `services/probe_service.py` | 预算/执行/计划 Workspace 从 Run/Diagnosis 反查，不再信任请求体 |
| `services/repair_service.py` | Sandbox Task/Run 显式继承 Repair Workspace；来源与血缘服务端校验（见 WP3 报告） |

## 4. 重要说明

- **platform-admin 按既定策略可跨 Workspace**：对 B 的 Repair `promote` 返回 409（状态机拒绝）
  而不是 403，证明授权层没有误伤管理员；报表明确区分"授权拒绝"与"业务状态拒绝"。
- 负向测试不只检查 HTTP 状态：每条用例都比对 `tg_task` / `tg_run` / `tg_evidence` /
  `tg_doc` / `tg_intent` 行数，并校验 DENIED 审计记录和 Evidence 的 `workspace_id` × `run_id` 组合。
- 认证关闭的开发模式仍保持既有行为（`principal_of()` 返回 `None`）；本验收在认证开启下执行。
