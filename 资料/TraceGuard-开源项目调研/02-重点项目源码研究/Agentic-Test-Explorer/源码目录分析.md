## 3. 关键观察

1. **行号漂移**：`ARCHITECTURE_GUIDE.md` 中标注的源码行号普遍比实际源码小（如 `compile_swarm` 文档标 :442、实际 :630），高度疑似源码在文档撰写后经过多次重构扩张，文档未同步。使用文档定位代码时需以实际源码为准。【源码 vs 文档声称】
2. **测试与实现同构**：`test_bug_extraction.py` / `test_browser_engine.py` 的测试用例与 `graph_base.py` / `engine.py` 的实现细节一一对应（连正则形状、失败注释文案都一致），说明测试是随实现演进的回归网，**证据可信度较高**。
3. **能力未接线**：`get_visual_validation_tool()`（`custom_tools.py:349`）实现了基于视觉模型的 PASS/FAIL 判定，但 `standard_graph.py` / `advanced_graph.py` 的工具装配列表**均未包含它**（`standard_graph.py:60-68`、`advanced_graph.py:65-73`）。即该"视觉 Oracle 雏形"在默认流程中未被启用。【源码】
4. **单库双用**：checkpoint 与 long-term store 均指向 `agent_memory.sqlite`（`main.py:436-437`），与架构文档所称的两个独立 db 文件不一致。【源码 vs 文档声称】
