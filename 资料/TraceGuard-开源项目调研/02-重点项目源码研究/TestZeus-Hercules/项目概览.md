## 1. 一句话定位

Hercules 是一个 **LLM 驱动的自动化测试执行框架**：以 **Gherkin Feature** 为输入，通过 **LangGraph 状态机**（planner → executor → assertion 三个节点）调度一组 LLM Agent + 确定性工具，驱动 Playwright 完成浏览器 / API / SQL / MCP / 安全 / Python 沙箱等测试，最终产出 **JUnit XML、HTML 报告、Markdown 报告、证据 bundle、SQLite 运行历史**。

README 原话（README.md:856-858）："Hercules runs on a LangGraph state-machine architecture... runtime is structured as planner, executor, and assertion graph nodes." —— 该声称与源码 `core/simple_hercules.py` 一致（见 `整体架构分析.md`、`核心执行流程.md`）。

## 5. 关键发现速览（供 TraceGuard 对照）

1. **不存在独立的 Assertion Agent 角色。** 源码中 `_assertion_node`（`core/simple_hercules.py:1386-1423`）只是一个**信任 Planner 输出的 `is_assert/is_passed/assert_summary` 并把终局 JSON 写入消息、结束图**的状态节点，其注释明确写着 "trusts planner's is_assert/is_passed/assert_summary"。真正的确定性判定由 `assert_ui` / `assert_json_path` 等**注册在导航 Agent 上的 Python 工具**完成。结论：**断言判定由"Planner 自报 + 可选的确定性工具 + 报告期断言账本校验"三段式构成，没有独立 Agent。** 这与 TraceGuard "Oracle 独立于 Agent" 原则存在本质差异。
2. **Agent 是执行能力层，且多数 verdict 由 LLM 自报**；Hercules 用"断言账本 + junit_helper 覆盖 + strict verdict + observer 不变量"来补偿，属于**事后校验型**可信机制，而非 Oracle 前置独立判定。
3. **证据留痕完善**：`assertion_logs.log`、`agent_inner_thoughts.json`、network/console 日志、video/screenshot、Playwright trace 均落盘，报告期可审计（与 TraceGuard "Event/Evidence / Evidence Graph" 有可映射之处，但 Hercules 未构建图结构证据链）。
4. **失败分类是启发式正则**（`healing/failure_classifier.py:80-132` 的 PATTERNS），分类置信度是"命中信号占比"（`:167-187`），属**推断性**而非因果判定（对应 TraceGuard "相关不等于因果"的关注点）。
5. **自愈不改断言**：`heal_proposer.py` 只提出/探测新 selector（`:232-255`），未见修改 `is_passed`/断言逻辑的代码路径（对应 TraceGuard "修复不得削弱断言"，但 Hercules 的自愈是 opt-in 的旁路模块，未接入主图）。

## 6. 主要风险与局限（速览，详见整体架构分析第 9 节）

- **AGPL-3.0 强 copyleft**（第 13 条仅针对修改版网络交互，非所有 SaaS 使用都触发源码披露）。
- **Playwright 版本锁定 `<=1.49.0`**。
- **复杂度高**：约 30+ Agent/工具/编排文件，singleton + 进程全局状态 + 子进程隔离，认知与维护成本大。
- **证据可信度依赖配置**：UI 断言、observer 不变量、失败分类、history、bundle 默认关闭；但 API 断言 `assert_json_path` 默认注册给 `api_nav_agent` 并写账本，报告期可覆盖虚假 PASS。默认 verdict 仍以 Planner 自报 `is_passed` 为准，零断言 PASS 仅标记 `Assertions Missing` 不判红。
- **安全边界**：`execute_python_sandbox` 暴露 page/browser/context/playwright_manager 给脚本（靠"沙箱"命名与租户白名单，需评估隔离强度）；heal 的 LLM 输入做了控制字符清洗但未做语义隔离（用 `<page_text>` 标记包裹，视为不可信内容）。

## 8. 结论

Hercules 是一个**工程成熟度高、可观测性与防御性编码扎实**的 LLM 测试框架，具备完整的企业级编排（并行隔离、suite、监控回归、历史 DB、报告）。但其**可信 verdict 的"事实层"并不独立于 Agent**，主要依赖"Planner 自报 `is_passed` + 默认注册的 API 确定性断言 `assert_json_path` + 报告期断言账本覆盖 + 多个 opt-in 强化项（UI 断言/observer/history 默认关）"，与 TraceGuard 所主张的"Oracle 前置独立、Agent 仅能力层"路线不同。加之 AGPL-3.0 强 copyleft 与 Playwright 版本锁定，作为 TraceGuard 的对照样本极具价值，但不宜直接作为可商用内核复用。
