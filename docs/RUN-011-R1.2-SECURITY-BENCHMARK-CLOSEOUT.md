## 2. 两个安全问题的根因与修复方案

### 2.1 TestCase 审核稳定性门禁的 HTTP 绕过入口

**根因**：`ReviewReq.require_stability: bool = True` 允许客户端传 `false`；
`review()` 路由把请求字段直接传给 `review_testcase(require_stability=req.require_stability)`；
服务层 `_stability_gate(require=False)` 返回 `SKIPPED_BY_CALLER`，使公开 HTTP API 可主动跳过
Compiler/Healed 候选用例的 STABLE_PASS 回放门禁。

**修复**：

- `apps/api/traceguard_api/routers/catalog.py`：`ReviewReq.require_stability` 约束为
  `Literal[True] = True`，客户端传 `false` 在 Pydantic 校验阶段即返回 422；
- 路由调用服务时固定 `require_stability=True`，不信任请求参数；
- `packages/persistence/traceguard_persistence/catalog.py` 保留
  `review_testcase(require_stability=False)` 作为**受信任的服务端内部**历史迁移/数据修复路径，
  并补充边界注释；该路径不再通过 HTTP 暴露；
- 未删除历史测试与历史夹具：RUN-011-R1.1 的 workspace 隔离夹具仍使用服务层豁免。

### 2.2 三个全局观测接口的 Workspace 信息暴露

**根因**：`action_for_request()` 对 GET 一律先映射为 `read`；viewer / qa-engineer / qa-lead 均拥有
`read`。而 `/api/v1/events/conflicts`、`/api/v1/probes/audit`、`/api/v1/inbox/stats`
分别直接返回跨 Workspace 的冲突列表、探针审计日志、Inbox 汇总，没有 Workspace 过滤。

**修复**：

- `packages/persistence/traceguard_persistence/auth.py`：新增 `system.observe`，
  权限集合仅 `{platform-admin}`；
- `apps/api/traceguard_api/auth.py`：新增 `GLOBAL_OBSERVATION_PATHS`，在通用
  `SAFE_METHODS → read` 映射**之前**优先判定上述三个接口（含尾斜杠变体），
  映射到 `system.observe`；中间件统一拒绝并记录 DENIED 审计；
- 权限矩阵由 `PERMISSIONS` 自动派生，`/api/v1/auth/permissions` 同步反映新动作；
- 未修改审计数据结构，未用前端隐藏菜单代替服务端鉴权。

**其他全局 GET 接口检查**（本轮审计结果）：

| 接口 | 检查结论 |
|---|---|
| `/api/v1/events/stats`、`/api/v1/queue/stats` | 已使用 `scope_filter`，仅返回授权 Workspace 范围，无同类问题 |
| `/api/v1/events/{id}`、`/runs/{id}/...`、`/probes/executions` 等 | 实体级 `require_entity_workspace` / `workspace_ids`，无同类问题 |
| `/api/v1/auth/permissions`、`/auth/me` | 仅身份/展示信息，不暴露 Workspace 业务数据 |
| `/api/v1/system/metrics` | 跨 Workspace 计数汇总，但**不含 Workspace 标识/明细**；本轮不改，登记为 NEEDS_DECISION |

  对范围外 Workspace 仍为 `WORKSPACE_FORBIDDEN` 403；

## 5. Benchmark v5 修正前后统计对比

计算入口：`scripts/bench_v5_run011_r1.py::compute_statistics()`，
离线读取原始归档，本轮**未重跑** 23 场景 × 2 轮。

| 字段 | 修正前 | 修正后（历史归档） |
|---|---|---|
| `execution_records` | 无（只看过滤后样本） | **46** |
| `execution_scenarios`（兼容字段 `scenario_coverage.total_scenarios`） | 19 | **23** |
| `diagnosis_sample_size`（兼容字段 `sample_size`） | 37 | **37** |
| `failure_scenarios`（兼容字段 `produced_failure_samples`） | 19 | **19** |
| `positive_control_records` | 无（9 条被混入过滤/丢弃） | **9** |
| `failure_scenario_coverage`（兼容字段 `scenario_coverage.coverage`） | 19/19 = 1.0 | **19/23 = 0.8261** |
| `false_pass_rate` | null（旧口径：GT=PERSISTENCE 且 F 臂预测非 PERSISTENCE/TIMING） | **0/37 = 0.0** |
| `false_pass_count` / `false_pass_denominator` | 无 | **0 / 37** |
| `unclassified_error_records` | 无 | **0**（历史 9 条异常均为 412 + run PASSED） |

口径要点：

- 全部执行记录、有效诊断记录、正向控制分开统计；正向控制不进入主因诊断准确率分母；
- 历史 `error` 记录只有同时满足 `412` 与 `run PASSED` 才识别为正向控制；
  其它异常仍计入 `unclassified_error_records`，不一律归类为正向控制；
- False Pass 改为 evaluator 级判定：只统计有有效 GT 的诊断样本，
  GT 期望失败但实际 Run Verdict 为 PASSED 才计数；F/G 臂预测机制不再参与；
- 保留旧臂名别名 `F_probe_aligned` / `G_probe_unknown_time` 的兼容读取；
- LLM / Probe Feedback / Time Alignment 分项目标值保持不变：
  LLM 成功 21/37、非法 JSON 16/37、Fallback 16/37、候选 63、成功子集 13/21；
  探针执行 54、反馈 54、假设更新 25（SUPPORT 15 / CONTRADICT 10）；
  时间对齐 108 条（POST_HOC 54 / UNKNOWN 54 / ALIGNED 0），无 Run 内 ALIGNED 探针；
  诊断延迟均值 17.5ms、Abstention Rate 5/37。

专项文件：`tests/unit/test_benchmark_v5_statistics_run011_r1_2.py`（9/9 通过），
覆盖原始 46 条记录、9 条正向控制排除、普通异常不误判、GT 失败 + PASSED 计数、
正常正向控制 PASSED 不计数、F/G 别名兼容、其它统计不变与归档 SHA-256 保护。
