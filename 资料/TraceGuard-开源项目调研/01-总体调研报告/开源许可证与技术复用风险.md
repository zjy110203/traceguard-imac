# 开源许可证与技术复用风险报告

- 核实时间：2026-11-18
- 依据：各项目官方仓库根目录 LICENSE 文件原文（逐一查看），辅以 GitHub API license 字段与官方 README/LEGALNOTICE
- 纪律：**研究学习 ≠ 代码复制；依赖引入 ≠ 复制源码；复制代码与分发衍生作品可能产生额外义务**。不能仅凭 README 的 License 标识下结论。
- 无法确定的许可证问题明确标记"待法律评估"。

## 三、高风险许可证专项说明

### 3.1 AGPL-3.0（TestZeus Hercules）— 最高风险

- **事实**：LICENSE 为 AGPL-3.0 全文；pyproject.toml 未声明 SPDX；版本 1.0.1，最后提交 2026-10-24（git log 已核）。
- **第 13 条准确含义**：AGPL-3.0 在 GPL-3.0 基础上增加第 13 条——若**修改了 AGPL 程序**，且该修改版支持用户通过网络远程交互，则须向这些远程交互用户提供获得修改版对应源码的机会。该条针对"修改后的程序 + 网络远程交互"这一特定情形，**不能简化为"所有使用 AGPL 软件的 SaaS 都自动要公开整个宿主平台源码"**。
- **需区分的情形**：①单纯学习/阅读源码不构成引入；②以依赖方式引入须按 AGPL 处理并保留声明；③复制/修改源码形成衍生作品并按 AGPL 分发或网络提供，才触发相应源码义务；④是否与 TraceGuard 构成需按 AGPL 处理的组合程序，取决于具体集成方式，需逐案法律评估。
- **结论（工程决策不变）**：**不得复制、移植、衍生 Hercules 源码进入 TraceGuard 正式代码库**。仅可学习架构与设计（Planner 结构化计划、AgentRegistry、报告产物组织、失败分类），用 TraceGuard 自有设计独立实现。是否引入任何形式的依赖须先做法律评估；当前决策状态"不采用/待法律评估"。

### 3.2 GPL-3.0（Neo4j）— 条件性风险

- **事实**：社区版 GPLv3（LICENSE.txt），企业版闭源组件需商业授权；默认分支 2026.10。
- **GPL-3.0 与 AGPL-3.0 的关键区别**：普通 GPL-3.0 **没有 AGPL 第 13 条那样的一般网络交互源码披露条款**。GPL 的源码义务主要在向他人**传递/分发**受许可软件（含衍生作品、组合程序）时产生；仅通过网络向用户提供服务，通常不等于 GPL 意义上的"分发"。AGPL 正是为填补这一差异而增设第 13 条。二者义务不可混用。
- **需区分的情形**：①内部运行通常无源码披露义务；②复制/修改源码形成衍生作品并按 GPL 分发时须提供对应源码；③是否与 TraceGuard 构成需按 GPL 处理的组合程序取决于集成方式；④以独立服务/API 方式调用通常不自动触发 GPL 源码义务；⑤企业版组件须遵守商业授权。
- **结论（工程决策不变）**：P12 图数据库必要性未定，v1.1 首期明确用 PostgreSQL 关系表。**当前不引入**；若未来 P12 通过且需引入，须先做 GPLv3 合规评估（复制/修改/组合/分发情形）与企业版授权评估。不能笼统地说"SaaS 网络访问即触发 GPL 源码披露"。

### 3.3 混合许可（Langfuse）— 边界风险

- **事实**：根 LICENSE 核心为 MIT Expat（Copyright 2023-2026 ClickHouse, Inc.）；`ee/`、`web/src/ee/`、`worker/src/ee/`、`packages/shared/src/server/ee/` 为 Langfuse Enterprise License（商业许可，无标准 SPDX）。
- **结论**：仅学设计（LLM 语义 trace + OTel 底座、Dataset/Experiments）。不得复制 `ee/` 目录代码。

### 3.4 元数据不一致（BrowserGym、AgentLab）— 澄清项

- **事实**：GitHub API license 字段为 Other/NOASSERTION；README 徽章文字显示 MIT 但链接指向 Apache-2.0；仓库根 LICENSE 文件为 Apache-2.0（Copyright 2024 ServiceNow）。
- **结论**：以 LICENSE 文件为准，认定 Apache-2.0。引用时以官方 LICENSE 为依据，不采用 API/README 徽章口径。

## 六、总体合规纪律（供团队遵守）

1. 研究学习不等于代码复制：阅读源码、做架构对照不构成引入。
2. 依赖引入不等于复制源码：通过包管理引入 MIT/Apache 组件，保留 LICENSE/NOTICE 即可。
3. 复制代码或分发衍生作品可能产生额外义务，尤其 AGPL/GPL。
4. AGPL 项目（Hercules）必须特别评估：第 13 条仅针对修改版网络交互情形，不泛化为所有 SaaS；当前结论仍为不引入。
5. 不凭 README 的 License 标识下最终结论，一律查看官方 LICENSE 文件。
6. 不确定项标记"待法律评估"，不由研究阶段自行裁决。
7. 所有引入须经评审，研究完成不等于批准采用。
